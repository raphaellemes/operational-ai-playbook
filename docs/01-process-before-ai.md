# Process Before AI

AI initiatives often begin with a question like:

> Which model should we use?

In operational environments, a better first question is:

> Which process is this AI system supposed to improve?

## Why This Matters

If the process is unclear, AI will not create clarity by itself.

It may generate better text, summarize faster, classify at scale, or produce a convincing recommendation. But if the underlying workflow has no owner, rule, source, or metric, the organization may only automate confusion.

## Process Questions To Answer First

Before implementing an AI workflow, clarify:

- What decision or activity is being supported?
- Who owns the process?
- Which inputs are required?
- Which source is considered authoritative?
- Which rules must be followed?
- What should happen when the AI is uncertain?
- What requires human validation?
- What evidence must be retained?
- Which metric proves the workflow improved?

## AI Maturity Shift

There is a practical difference between testing AI, using AI, and operating with AI.

| Stage | Description | Risk |
|---|---|---|
| Testing AI | Experiments, prompts, proofs of concept | Learning without operational commitment |
| Using AI | AI supports individual tasks | Gains may remain isolated |
| Operating With AI | AI becomes part of the process | Requires governance, ownership, logs, metrics |

## Practical Rule

If the team cannot describe the process without AI, it is too early to automate it with AI.
